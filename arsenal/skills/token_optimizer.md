# 渗透场景下的 Token 与上下文经济

省 token 的前提是不牺牲渗透效果——该读的全文不能省，该做的单点验证不能跳。原则是「省掉重复与噪音，保留关键证据」：

1. 扫描结果看预览、源码/配置读全文：nmap/目录爆破这类纯扫描输出外置后看预览即可；但读源码、读配置文件、读可疑文件时，必须 `read_artifact` 读完整内容——flag 线索、硬编码凭据、隐藏路由常藏在后半段，为省 token 只看预览是本末倒置。

2. exp/poc 脚本落地执行：利用脚本先 `write_file` 写文件，再 `shell` 执行 `python3 <文件>`——避免整段脚本反复塞进命令参数（既烧 token 又易出错），脚本也便于反复迭代。

3. 批量优先、单点不跳：多 payload/路径/参数能用 `fuzz` 一次归组的用 fuzz（响应差异即注入点）；互不依赖的探测用 `parallel_shell`；独立漏洞分支用 `spawn_subtask`。但需要精细控制或单点确认效果时，仍要单独发请求，不能为省 token 跳过验证。

4. 已确认结论写黑板不重复：漏洞/端口/版本/入口写 `blackboard`（注入摘要，全文用 `blackboard get <key>`）；每轮别复述已知信息，判死方向用 supersedes 取代旧结论。

5. think 用在刀刃上：关键决策点（分析工具输出、构造 exp 前）用 think 梳理思路，值得；但不要在无新信息时反复 think 占 token。

6. 先查 CVE/POC 再打，查不到就探索：指纹后先 `search_cve` / `find_skills` / `list_knowledge` 查现成打法（快）；查不到或不符合时，回到第一性原理（技术栈反推 + 差异实验）自己探索，别在「反复查同一个词」上空转。
